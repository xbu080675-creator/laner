# Laner Project Scope

## 项目定位

Laner 是现有电竞观赛助手的下一代重构工程。

本轮重构的产品原则只有两句：

> **功能不改。**
>
> **底层重做。**

旧版本承担行为基线与功能参考，新仓库承担新的长期可维护实现。

## 当前阶段

- 阶段：`M0 / Project Foundation`
- 当前任务：`LNR-000`
- 状态：`IN PROGRESS`
- 业务代码：尚未开始
- 旧工程功能基线：待提取

## 本轮允许改变的内容

- 模块边界与目录结构；
- Core / Application / Port / Adapter 架构；
- 数据标准化与数据源接入方式；
- 赛事状态机 / Event Engine；
- 网络层、缓存、数据库和持久化；
- 后台任务与轮询调度；
- OCR / AI / 外部源接入方式；
- 日志、错误码、诊断、测试、构建和 CI；
- 内部接口，只要不无故改变外部可见行为。

## 本轮默认禁止改变的内容

在形成 `FEATURE_BASELINE.md` 并逐项迁移前，默认禁止因“重构方便”而删除、缩水或静默改变：

- 现有用户可见功能；
- 已确定的赛前 / 赛中 / 赛后产品分区；
- 已存在的核心数据展示能力；
- 已确定的赛事辅助定位与交互逻辑；
- 现有关键 UI 行为和用户操作习惯；
- 已验证的数据能力。

如某项确实必须变化，必须单独立项、记录原因、兼容影响和验收方式。

## 旧工程使用方式

旧工程只作为：

1. 功能清单来源；
2. 行为基准；
3. UI/交互参考；
4. 数据格式与历史问题参考；
5. 回归对照。

旧代码不得未经审查直接复制到 Laner。

## 正式业务开发前置条件

在开始首个业务功能迁移前必须完成：

- `docs/ENGINEERING_CONSTITUTION.md`；
- `docs/FEATURE_BASELINE.md`；
- `docs/ARCHITECTURE.md` 的目标架构冻结；
- `docs/DEVELOPMENT_PLAN.md` 的首批任务拆分；
- 测试策略、日志规范、错误码基本规则；
- 当前旧工程真实状态读取与基线记录。
