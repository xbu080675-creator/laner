# Laner UX Principles

## 体验总原则

Laner 的交互与视觉以两个词为准：

> **极简**
>
> **酷炫**

但优先级固定为：

```text
信息清晰 / 操作直接
>
视觉表现 / 动效氛围
```

也就是说：先保证极简，再在不损害理解和操作效率的前提下做酷炫。

## 极简

极简不是“功能少”，而是：

- 用户在当前比赛阶段只看到此刻真正重要的信息；
- 重要结论优先于原始数据堆叠；
- 常用操作尽量 1~2 步到达，原则上不超过 3 个主要步骤；
- 不要求用户理解内部数据源、Provider、缓存、OCR 或 AI 管线；
- 不重复展示导播已经清楚给出的信息，除非 Laner 能提供额外解释价值；
- 不用大量常驻卡片抢占屏幕；
- 页面信息层级必须一眼可扫；
- 观众默认看到结论与原因，深度数据按需展开；
- 教练/分析人员可以下钻，但首屏同样保持明确的优先级。

## 酷炫

酷炫必须服务电竞临场感，而不是装饰性炫技。

可以使用：

- 清晰的阶段切换动画；
- 关键事件的空间化 HUD；
- 数字滚动、变化趋势与差值动画；
- 资源、经济、等级、节奏变化的动态图形；
- 关键节点的短时强调；
- 沙盘、时间线、局势图等信息可视化；
- 低延迟、短时长、可打断的转场与反馈；
- 电竞风字体层级、边框、光效和动效语言。

禁止：

- 为了好看延迟信息出现；
- 长动画阻塞用户操作；
- 大面积高亮导致视觉疲劳；
- 持续闪烁、无意义粒子、过量发光；
- 低对比度“赛博黑”导致正文难读；
- 用动效掩盖数据不确定性或状态错误；
- 每条普通数据都做成强提醒。

## 三阶段下的体验目标

### PRE_MATCH / 赛前

体验关键词：**安静、准备、建立预期**。

用户应快速获得：

- 今天打谁；
- 谁首发；
- 双方近期状态；
- 这场比赛重要在哪；
- 哪些对位与变量值得提前看。

视觉表现以组织信息和建立比赛预期为主，不应制造赛中级别的持续紧张感。

### LIVE_MATCH / 赛中

体验关键词：**实时、聚焦、临场**。

这是酷炫程度最高的阶段，但也必须最克制。

优先展示：

- 当前局势；
- 刚刚发生了什么；
- 为什么重要；
- 下一窗口在哪里；
- 导播没展示或尚未展示的重要信息。

关键事件可以强动效强调，但必须有 TTL，自动退场，不得长期覆盖比赛画面。

### POST_MATCH / 赛后

体验关键词：**沉淀、解释、复盘**。

比赛结束后视觉节奏应主动降下来，将实时 HUD 转换为：

- 结果；
- 关键时间线；
- 胜负转折；
- 数据对比；
- 复盘与结论；
- 后续积分 / 晋级影响。

赛后不需要继续维持赛中高强度动态效果。

## 信息优先级

任何页面与 HUD 元素在设计时都必须有 Priority：

- `P0`：必须立即知道，例如比赛阶段变化、关键资源结果、重大状态异常；
- `P1`：当前很重要，但可在数秒内读取；
- `P2`：辅助理解，按需展开；
- `P3`：历史、背景、深度资料，可下钻查看。

首屏不得被 P2/P3 信息挤占。

## 动效原则

所有正式动效必须回答：

1. 它在表达什么状态变化？
2. 不做这个动效，用户会不会更难理解？
3. 动效多久结束？
4. 能否被中断？
5. 低性能设备或减少动画模式下如何降级？

答不出来的动效默认不做。

## 性能与无障碍底线

酷炫不得牺牲：

- 触控响应；
- 滚动流畅度；
- 低端或高负载设备下的可用性；
- 字体与数据可读性；
- 色彩之外的状态表达；
- 减少动画（Reduced Motion）模式；
- 重要信息的文字/符号冗余表达。

## 设计验收口令

每次页面或 HUD 设计完成后，必须问：

> **够不够简单？**
>
> **够不够有电竞感？**
>
> **酷炫有没有妨碍我看比赛？**

如果第三个问题答案是“有”，必须优先删减视觉效果。
