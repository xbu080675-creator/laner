# LNR-022 产品表层兼容事故记录

- Task: `LNR-022 — Product Surface Compatibility Remediation`
- Incident: `INC-LNR-022-001`
- Date: 2026-09-13
- Baseline: `main@739430d7d8a234bf4ab00ac4004c3745772e26d7`
- Status: `OPEN / REMEDIATION REQUIRED`
- Trigger: 用户在 Block 3 开始前实机试玩 Block 1+2 APK，确认产品表层与旧 RiftLab 行为基线不一致。

## 1. 事故结论

本事故不是新的产品改版需求，而是对既有迁移约束的纠偏。

`docs/PROJECT_SCOPE.md` 已明确：

> **功能不改。底层重做。**

并明确禁止因重构方便静默改变现有用户可见功能、关键 UI 行为和用户操作习惯。

当前 Laner 在此处发生了三类偏离：

1. **普通用户根页面暴露 Riot credential 配置。** 旧 RiftLab 的 Riot/Cito/LPL/International 等来源属于后台 Provider/Source Orchestration；用户面对的是标准化赛事事实，而不是 Provider 密钥管理。Laner 当前把 `RiotCredentialPanel` 放到一级根页面，错误地把开发/诊断配置升级成普通产品前置条件。
2. **主 APP 产品壳被重新设计。** 旧 RiftLab 的切角、Rift 视觉 token、Header、三阶段导航、信息密度与操作习惯被新的普通 Material 圆角壳替代。重构底层不构成更换前台的授权。
3. **大型 RiftScreen HUD 结构被缩水/改形。** 旧 `RiftOverlayView` 已有 MINI / COMPACT / EXPANDED 三档、队伍标识、中心经济差、K/T/D、GOLD/LEAD、Event、尺寸提示与短时强调。Laner 当前 `RiftScreenOverlayView` 改成新的简化结构；用户明确要求大的 HUD 继续沿用旧设计，允许优化实现但不允许改掉产品形态。

## 2. 相关宪法/项目条款

- 工程宪法 §0.3：发现违规必须停止扩展、修复或回退、重测、合规复查后继续。
- §1 / §1.1：从最新仓库事实重新 Preflight。
- §3.6：外部能力可替换、可降级；第三方 Provider 不得成为普通产品路径的隐性硬依赖。
- §4：未经明确批准不得改变 UI / 操作习惯；冻结阶段出现架构/产品基线破坏必须单独立项修复。
- §6：Debug/Admin 能力必须与普通路径隔离。
- §9：正向、负向、边界、非目标与永久回归。
- §10：UI 不得成为业务真相来源。
- `PROJECT_SCOPE.md`：功能不改、底层重做；旧工程是 UI/交互参考与回归对照。
- `UX_PRINCIPLES.md`：不要求普通用户理解 Provider、缓存、OCR 或 AI 管线。
- `FEATURE_BASELINE.md`：LIVE-024~030 的 Overlay/HUD 属于迁移基线，不得因重构缩水。

## 3. 修复范围

### 3.1 普通用户数据源体验
- 从普通 `LanerRoot` 删除 Riot credential 面板及相关参数。
- `MainActivity` 不再承担 runtime Riot key 编辑状态。
- 保留 `LanerApplication` / Adapter 的内部 credential 注入能力，用于受控 BuildConfig/CI secret 或未来开发者诊断入口。
- 本任务不把任何 secret 写回 Git，也不重新引入旧版硬编码 API key。

### 3.2 主产品壳兼容
- 恢复 RiftLab 的视觉语言：默认 Rift palette、切角、Header、三阶段一级导航、旧信息密度与背景语言。
- 产品名继续使用 `LANER`，因为这是已明确的新项目名；除此之外不借机重新设计业务流程。
- `CompetitionStructurePanel` 不再作为根页面额外插入的大块一级 UI；竞争结构能力保留在既有 PRE 功能内部/后续兼容入口，不因本修复删除底层能力。

### 3.3 大型悬浮 HUD 兼容
- `RiftScreenOverlayView` 恢复旧 `RiftOverlayView` 的产品形态：MINI / COMPACT / EXPANDED 三档、中心对局/经济差、K/T/D、GOLD/LEAD、Event/Status、旧尺寸与视觉层级。
- 输入继续使用 Laner `RiftScreenPresentation`，不恢复旧 `MatchSessionStore` / `MatchTimelineStore` 依赖。
- Draft HUD / Tactical HUD 本任务不重画、不缩水；只做必要兼容，避免误伤。

## 4. 明确不做

- 不启动 Block 3 Watch Hub / Player。
- 不回退 Block 1/2 的 Core/Application/Timeline/Event/OverlayWindowHost 架构。
- 不复制旧 Store、旧 Repository 或旧 Provider arbitration。
- 不引入旧仓库硬编码 Riot API key。
- 不借机增加新功能或重新设计 Draft/Tactical HUD。

## 5. 验收条件

1. 普通用户根页面和 MainActivity 不再出现 Riot credential 输入/保存/清除操作。
2. Riot Provider 仍能通过内部受控 credential 注入工作；没有 credential 时显式降级，不把配置责任转嫁给普通用户。
3. 主壳恢复 RiftLab 风格：Header + 三阶段导航 + Rift palette/cut-corner/background；不再由新的普通 Material 根壳主导。
4. 大 HUD 恢复旧三档尺寸与信息层级，且数据只来自 Laner Presentation。
5. Draft/Tactical 现有行为不被本任务改坏。
6. CI 增加产品表层兼容门禁，禁止 `RiotCredentialPanel` 再次接入普通根页面/MainActivity。
7. Architecture / Core / App Unit / Android assemble / APK upload 全部 PASS。
8. 实机视觉、拖动、悬浮权限、横竖屏继续如实标记 `WAITING EXTERNAL TEST`，不得用 CI 冒充。
